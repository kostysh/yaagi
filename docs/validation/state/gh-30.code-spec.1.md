## Remediation

- Первопричина: metadata helper повторно читал изменяемый optional sidecar вместо проверки уже полученного Stats. Штатная очистка SQLite ошибочно трактовалась как потеря DB.
- Прямой blast radius: проверка DB/WAL/SHM при открытии и scoped SQL. Обязательная DB, owner/mode/type и отсутствие стороннего fd open/close должны сохраниться.
- Коррекция: проверить один полученный Stats; без queue/lock/retry и без изменения контрактов.
- Проверка: сохранить детерминированный public witness в существующем fault preload, получить PASS concurrent check и следующей операции; прежние private-file/missing-DB tests остаются обязательными.
- Коррекция выполнена: `checkPrivateFile(Stats)` сохраняет mode/uid/type checks; `databaseFiles` больше не перечитывает optional path. Новая регрессия встроена в существующие `fault-hook`/`fault-child`, использует настоящий reader и checkSchema; после штатного удаления WAL проверяет следующий check, write и reopen.
- Evidence: regression на прежнем dist `0605b85` → FAIL с unavailable; после исправления → PASS. Root format/format:check, Biome+ESLint+boundary, typecheck/build/test, guide example, diff check → PASS; state **50/50**, без skipped. Прежние missing-DB и private mode/symlink tests проходят. Дополнительно проверены pure error mapping и backup committed WAL при удерживаемом старом snapshot.
- Статус remediation: `verified` локальными проверками; независимый delta verdict ожидается. Исходный FAIL сохраняется.
