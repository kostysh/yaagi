## Remediation

Первопричины: SQL wildcard `_` принят за буквальный символ; callback и adapter errors направлялись в один классификатор без учёта происхождения. Исправлены все три prefix queries (`GLOB 'sqlite_*'`) и отдельный catch awaited callback; SQL poison остаётся первичным. Добавлены regression tests для обоих отказов и reuse/rollback.

Прямое наблюдение по migration guard также исправлено: private SQLite authorizer отклоняет реальные connection/transaction operations, включая END, и снимается перед техническим journal/cleanup. Никакого SQL parser/framework или публичного API не добавлено. Допустимость обычных data literals/CASE/trigger следует прежнему контракту owner SQL; старое regex-ограничение было дефектом реализации, а не новой нормой CP1. Guide теперь описывает фактический механизм. Проверены целый batch rollback, отсутствие persisted DDL/journal и положительные literals/CASE/trigger fixtures.

После исправления: root format/format:check, dual lint/boundary, typecheck, build, test — PASS; **27 tests**, без failed/skipped; `git diff --check` PASS. Публичные signatures, зависимости и нормативная спецификация не изменены.
