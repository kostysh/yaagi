## Результат и граница

Production `createConstitution → checkBoot → Result` разрешает согласованный состав и отклоняет отсутствующую/повреждённую policy, несколько операторов и несовпадение фактического manifest/schema. Policy копируется при валидации и рекурсивно замораживается; порт, admission и ошибки неизменяемы. Исправление фактических входов допускает повтор без скрытого latch. Ошибки ограничены `denied` и пятью reason-кодами.

Это проверка чистого публичного API. Она не подтверждает реальный boot cell, OS lock, socket peer credentials, сохранённые схемы БД, модельные bindings из работающего органа, полномочия действий или approvals. Все значения fixtures синтетические. I1 с реальными соседями — #50; E3 остаётся gate действий соответствующего состава. C2/C3 и вся #46 не объявлены завершёнными.

Allowed manifest, фактический manifest и registered schemas заданы независимо. Production tests меняют фактическое значение при прежней policy; успешный double или schema-only validation эти проверки не заменяют. Тесты импортируют публичные package exports, не private source.
