## Результат и пределы

**Capability:** public input → общая/domain validation → owner Drizzle mapping → реальный временный файл SQLite через state → immutable публичный readback → reopen. Резервируются тики, сохраняются decide/settle и interrupted attempt, sequence монотонен. **Substrate:** contracts/SQLite entrypoints, одна owner-таблица и release SQL, package/type/integration checks, M1 и выполняемый guide.

**Anti-claims:** технические agent/action/outcome/policy/snapshot fixtures не доказывают существование foreign records, authority/freshness, consistent snapshot mapping или работу cognition/модели. M1 double не доказывает durability. T1 не принимает общий I1, runtime, субъективный цикл, живую Полифонию или E3. Нет реального model/dispatch/S3/transport; эти строки negative matrix неприменимы. Root отвечает за exclusivity и остановку прежнего исполнителя перед resume; epoch не является lease. Бюджеты/cancellation/storage errors принадлежат state, без второго retry/budget сервиса.

## Проверенные инварианты

| Требования | Production evidence |
| --- | --- |
| R1/R14 | Неверные входы/ключи/refs дают bounded invalid_input. Невалидные JSON/schemaVersion/phase/revision/frame/ref/previousCompleteTick/agent metadata и более старый active record дают incompatible; readback сохраняет повреждённый body без автоматического reset |
| R2–R4 | Две независимые state transaction на одном файле: один reserve подтверждён, второй conflict. Global TickId не переиспользуется через другой agent binding. Unique agent/sequence и partial unique active index; sequence после reopen/interrupted растёт, gaps читаются как отсутствие, overflow MAX_SAFE_INTEGER — conflict |
| R5–R7 | Decide только из reserved, settle только из decided с прежним actionRef; повтор/stale phase, чужой binding, неверный порядок/action отклоняются. Unknown outcome остаётся settled и становится previousCompleteTick |
| R8/R9 | После close/reopen reserved → interrupted без выдуманного action/outcome; decided сохраняется и требует явного settle. Повтор resume terminal записей ничего не меняет |
| R10/R11 | Owner failure после reserve/decide/settle, SQL failure после write и cancellation не оставляют частичного commit; sequence не расходуется. ReadSnapshot не может сохранить reservation; после непригодного state root выполняет close/reopen |
| R11, commit acknowledgement | Через публичный StorageAdapter seam тест после настоящего SQLite COMMIT возвращает внешний write_failed. Root закрывает state и authoritative readback после reopen находит reserved; callback выполнен один раз, повтор ID отклонён. Это моделирование потери подтверждения на публичной границе, не реальный SIGKILL/fsync fault или E3 |
| R12/R13 | Все шесть modes, разные epoch/tokens, wall clock rollback, safe-integer endpoints и signed zero проходят реальный round trip. Mutable reserve/outcome input после вызова не меняет результат/БД; record/frame/ref frozen, прежний DTO не меняется при переходе |
| M1 | Один неизменный consumer и одинаковые success/conflict/recovery scenarios с production TimelinePort через state и ограниченным независимым test-only double; double не использует production schemas/parsers и не выбирается production API |
| Imports/schema | Contracts/root без Node/native/SQL runtime imports; types: [] compile gate. Boundary probes блокируют hidden/runtime/private imports. Child из постороннего cwd импортирует exports без открытия БД и загружает настоящий built SQL |
| Migrations/body compatibility | Production release SQL: fresh/repeat, полный rollback ошибочной pending chain, отказ изменённого применённого artifact с сохранением истории. Первая схема: upgrade неприменим без реального schema delta; существующие SQL не редактируются |
| Guide | [examples/usage.ts](../../../packages/timeline/examples/usage.ts) исполняется через public exports: settled success, duplicate conflict, close/reopen/resume и следующий sequence 3. State закрывается до cleanup |

Прямые проверки — [timeline.test.ts](../../../packages/timeline/test/timeline.test.ts), [migrations](../../../packages/timeline/test/migrations.test.ts), [M1](../../../packages/timeline/test/m1.test.ts), [packaging](../../../packages/timeline/test/packaging.test.ts), [guide](../../../packages/timeline/test/guide.test.ts) и [type contracts](../../../packages/timeline/test/contracts.types.ts). Новый runner/harness не добавлен; node:test и публичный state используются по принятому baseline. Дубликаты, competing writes, terminal replay, invalid/stale input, read/write failure, rollback и retry/readback после частичного подтверждения покрыты по соответствующим строкам negative matrix. Live executor/replay вне T1; resume требует уже обеспеченного root отсутствия прежней работы.

Self-check R1 воспроизвёл пропуск лишнего symbol поля стандартной enumerable-key strictness Zod: адресный тест ожидал invalid_input, но получил сохранённый reserved (exit 1, `/tmp/yaagi-timeline-cp2/exact-keys-before.log`). Production input boundary теперь сравнивает все own keys сырого входа с проверенным DTO через Reflect.ownKeys; symbol/non-enumerable extras отвергаются, корректные значения не меняются. Обе отрицательные строки вошли в прошедшие 18 package tests; после изменения повторены обязательные root gates. Это находка авторского self-check до независимого аудита, не отрицательный audit verdict.

JSON mapping сохраняет `-0` только для двух time fields через явный storage token; строковое время на публичном входе по-прежнему отвергается. Pure contracts используют общие #45 parsers, SQLite mapping — только public scope state.
